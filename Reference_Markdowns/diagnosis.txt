The root cause of all these failures was **Software Rot**: You are building 2016-era research code (LLVM 3.8) on a modern 2020-era operating system (Ubuntu 20.04). We had to manually bridge the gap between old code and new compilers.

Here is the summary of the critical steps required to fix the PROMPT installation:

### **Phase 1: Fixing the C++ Backend (PROMPT)**

This was the battle to get `make` to reach 100%.

1. **Fixed the "Dual ABI" Linker Error**
* **The Error:** `undefined reference to llvm...[abi:cxx11]`
* **The Fix:** We forced CMake to use the old C++ string format to match the legacy LLVM libraries:
`cmake -DCMAKE_CXX_FLAGS="-D_GLIBCXX_USE_CXX11_ABI=0" ..`


2. **Fixed Missing Headers**
* **The Error:** `fatal error: ./Z3Builder.h: No such file`
* **The Fix:** We located the missing file in `lib/Expr` and manually copied it to `lib/Core` so `Executor.cpp` could find it.


3. **Patched the "Muqi" API Mismatch**
* **The Error:** `Executor.cpp` called `construct_muqi`, but the library only had `construct_muqi_solver`.
* **The Fix:** We injected a C++ shim into `Z3Builder.h` to translate the function call.
* *Correction 1:* We initially made it `private`; we had to move it to `public`.
* *Correction 2:* We initially used `int`; we had to change it to `int*` to match the pointer types used in the source.

### **Phase 2: Fixing the Python Frontend (Angr/PyVEX)**

This was the battle to get `import angr` to work without crashing.

4. **Downgraded Capstone**
* **The Error:** `AttributeError: module 'capstone' has no attribute 'CS_ARCH_ARM64'`
* **The Fix:** Pip installed an alpha version (6.0). We forced a downgrade to the stable version compatible with D-Helix: `pip install capstone==5.0.1`.


5. **Fixed Missing Submodules**
* **The Error:** `vex submodule not cloned correctly`
* **The Fix:** The repository was empty. We ran `git submodule update --init` to download the actual VEX source code.


6. **The "Sledgehammer" Fix for PyVEX**
* **The Error:** `error: Couldn't find make in PATH` (Ghost Error)
* **The Fix:** The build script was flawed and falsely claimed `make` was missing. We edited `setup.py` and replaced `sys.exit(1)` with `pass`, forcing the script to ignore the error and compile anyway.
